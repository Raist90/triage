# UI rework — decisions

Companion to `mock/ui-rework-plan.md`. Every blocking question in the plan is
resolved here; the code follows these answers.

| #   | Decision                                     | Detail                                                                                                                                                                                                                                       |
| --- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | **Adopt inline review findings.**            | Findings render as threads under their diff line. `AGENTS.md` + `.skills/frontend/SKILL.md` updated.                                                                                                                                         |
| D2  | **Keep fullscreen.**                         | Icon button in the 44px detail bar; hides rail, repo panel and list. The mock omitted it for artboard clarity only.                                                                                                                          |
| D3  | **Keep every diff control, relocate it.**    | File search, kind filters, sort, low-focus, focus mode, walkthrough/path mode and the semantic map move into the `Files` popover in the strip. Semantic map is now **off by default** (`showSemanticRail: false`).                           |
| D4  | **Remove the file rail.**                    | One scroll. `j`/`k` move between sticky 44px file headers, open the landed file and flash it.                                                                                                                                                |
| D5  | **Responsive right bar.**                    | 300px at `wide` (1400px). Below 1400 it is hidden by default and toggled from the detail bar (`reviewBarOpen` in Zustand). List stays 340px; the mock's 376px is artboard-only.                                                              |
| D6  | **Omit Reply.**                              | No reply/publish contract. A finding exposes Apply patch only; publishing stays out of MVP.                                                                                                                                                  |
| D7  | **ReviewPanel lives at the top of the bar.** | Rendered above the scrollable Review/Conversation/Explain sections when `review.open`. Escape priority unchanged.                                                                                                                            |
| D8  | **44px bands.**                              | Detail bar, diff strip and bar footer share `h-11`; the old 52px place footer is gone.                                                                                                                                                       |
| A1  | **Strip lives inside `DiffView`.**           | DiffView owns the diff control state (filter, focus, cosmetic, path step, popover), so it renders `DiffStrip` above its scroller. This keeps one source of truth without a control context; the plan's component tree is preserved visually. |
| A2  | **Inline-thread toggle scope.**              | `showDiffComments` hides GitHub inline comment threads and composers. Review finding threads stay visible: they are the review output the bar's footer produces.                                                                             |
| A3  | **No file-level comment button.**            | The mock's per-file comment action needs a file-anchored comment API that does not exist; findings and line comments cover the flow.                                                                                                         |
| A4  | **Finding anchoring is new-side first.**     | A finding anchors to the first line whose `newNumber` matches; removed files fall back to `oldNumber`. A finding that matches no rendered line is kept in the bar index and still focuses its file.                                          |
| A5  | **Fullscreen and bar persistence.**          | Neither is stored; both reset with the pane. `reviewBarOpen` defaults to false and only matters below 1400px.                                                                                                                                |
| A6  | **Expanded Context is capped.**              | The body scrolls inside a `40vh` box instead of pushing the strip and diff out of the pane; long PR bodies stay readable without losing the code.                                                                                            |
| A7  | **Opening the review form opens the bar.**   | Below 1400px the form lives in a hidden bar, so Manage → Request changes also sets `reviewBarOpen`; otherwise a focused textarea would be invisible.                                                                                         |
| A8  | **Rectangular chrome stays one line.**       | Strip facts are `whitespace-nowrap`; a file header puts status/cosmetic/signals/comment count into one truncated meta line that hides below 560px of document width. Verified at 1440 and 1180 in the running app.                           |
