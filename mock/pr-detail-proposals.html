Baseline — what the pane does today

The deck landed around the old detail pane. It still opens with a 44px command bar holding two primary buttons and four outlines, then repeats the PR title and list facts, then adds a tab strip. The preflight is a 76ch column floating inside 808px. The pane is calm, but it is not the calm the deck just established.

  • Two primaries. Approve and Squash merge are both lit; Review, draft, close and the two icons compete on the same line.
  • Title twice. The bar identifies the PR; the header renders the same identity at 20px with checks and change stats again.
  • Second navigation. The tab strip sits next to the app rail; the deck has no equivalent line.
  • No decision point. Context is raw markdown and the actions fall below the fold of a narrow column.

Evaluation — what to trade, and what to ship first

Read the three frames as the same pane at the same 808px width. The difference is not visual polish; it is where navigation, context and actions live. The ratings below are about fit with the deck, not about implementation taste.

  • A is the migration path: keep every tab, fix the chrome and action hierarchy.
  • B is the target: delete the tab strip, make deep surfaces places, keep recent conversation inline.
  • C is the context bet: persistent facts rail, shorter main column, actions in the rail.

Staged path
01

Ship A’s action hierarchy now. One primary in the footer, Manage menu for approve/draft/close/merge. Independent of the navigation decision and fixes the loudest baseline problem.

02

Adopt B’s information order. Title, why, context, risk, changes, recent conversation. This can land on A’s tab model before the places exist.

03

Remove the tab strip when Review becomes a mode. That is the dependency. Keep Conversation and Diff as places with a visible return to the briefing.

04

Try C only if Linear becomes the primary context. The facts rail is excellent for context and poor for prose width; do not run it alongside A’s tabs.

Recommendation

B is the target.
A is the bridge.
C is a bet on Linear.

B is the only proposal that removes a navigation layer instead of restyling it. The deck’s calm comes from one rail, one list, one pane; a tab strip directly under a repeated header re-creates the old app inside the new one.

  • B’s risk is discoverability. Conversation must stay visible: two recent entries inline plus a counted place in the footer. Do not hide it behind an overflow menu.
  • A’s value is sequencing. One primary action and a Manage menu can ship today without deciding where Conversation lives.
  • C’s value is context. If Linear acceptance criteria drive review, a persistent rail beats a card that scrolls. It costs 252px of prose width and a second focus region.
